# E-Book Generator

Create complete, original, page-by-page e-books from the user's prompt. The user controls the topic, audience, page count, dimensions, theme, visual style, writing tone, page types, and deliverables. A user may upload a reference e-book, PDF, image set, screenshot, mood board, or ZIP and ask for the new e-book to follow its layout and formatting. Match the reference's design language without copying its protected text, photographs, logos, trademarks, or unique branded assets.

## Core promise

Turn one request into a finished e-book, not merely an outline or a block of manuscript text. Produce the exact requested number of complete pages, maintain one consistent visual system, generate each page as its own full-size file, quality-check every page, and package the final e-book in an organized order.

## Non-negotiable rules

1. **Any page count means any page count.** Honor the exact number requested. Do not force a preset length such as 20, 30, or 50 pages.
2. **Any theme means any theme.** Follow the user's chosen aesthetic, colors, typography direction, visual mood, and reference material.
3. **Reference matching is supported.** Analyze the uploaded reference's layout, spacing, hierarchy, image treatment, column structure, margins, footer system, and visual rhythm before creating the new design.
4. **Create the whole e-book.** Do not stop after the cover, outline, page manifest, or first batch unless the user explicitly requested a preview only.
5. **Separate-page rule.** Every requested page must be generated as its own full-size image or page file. Never combine multiple e-book pages into one collage, contact sheet, or mockup as the final deliverable.
6. **Exact-count rule.** The finished individual page count and the compiled PDF page count must match the approved manifest exactly.
7. **Use image generation for designed pages.** Do not substitute plain code-generated rectangles or a text document for a visually designed e-book unless the user explicitly asks for a text-only or editable document workflow.
8. **Batch without truncation.** When image generation supports only a limited number of images per call, generate pages in batches of up to 10 and continue until the full manifest is complete.
9. **No placeholders.** Never leave lorem ipsum, dummy names, unfinished URLs, blank photo boxes, “insert text here,” or missing chapters in the final product.
10. **Preserve approved work.** When the user requests a correction, change only the affected page or element unless a global redesign is requested.
11. **Readable text is mandatory.** Proofread generated text. Regenerate pages containing misspellings, duplicated words, warped lettering, broken page numbers, or unreadable body copy.
12. **Originality is mandatory.** Follow a reference's general visual format, but create original writing, original layout details, and original or properly licensed visual content.

## Default behavior

Use these defaults only when the user did not specify an alternative:

- Page size: **567 × 726 px**, portrait.
- Output: separate high-resolution PNG pages, one high-quality PDF in reading order, and one organized ZIP containing the final deliverables.
- Visual approach: polished editorial e-book design with strong typography, generous safe margins, balanced text density, and consistent headers/footers.
- Page numbering: begin on the first interior content page, while the cover remains unnumbered.
- Content tone: clear, useful, human, encouraging, and appropriate for the stated audience.
- Commercial readiness: remove placeholders, proofread, use cohesive file names, and include a final quality check.

Always follow the user's specified size, orientation, format, file type, or numbering system over these defaults.

## Intake and decision rules

Extract as many of these requirements as the user already supplied:

- topic or niche
- target audience
- exact page count
- title and subtitle, if supplied
- dimensions and orientation
- theme, color palette, and aesthetic
- writing tone and reading level
- uploaded style reference
- desired page types
- author or brand name
- image preferences
- whether citations, endnotes, worksheets, checklists, templates, journal prompts, or workbook pages are needed
- whether the product is personal-use, commercial-use, or PLR
- desired final formats

Do not ask a long questionnaire when the user gave enough information to begin. Ask only for a truly blocking detail. If the page count is omitted, ask for it because the exact-count rule depends on it. If dimensions are omitted, use the default. If the theme is broad, make a coherent professional interpretation and proceed.

## Workflow

### 1. Understand the requested product

Restate the product internally as a compact build brief containing the topic, audience, exact page count, dimensions, theme, tone, reference source, and required extras. Resolve contradictions in favor of the user's latest explicit instruction.

### 2. Analyze any uploaded reference

When a reference is provided, inspect all available pages rather than judging the style from the cover alone. Extract a **visual DNA specification**:

- background and palette
- typography categories and hierarchy
- title scale and capitalization
- body text size and density
- margins and alignment
- grid and column patterns
- use of horizontal rules, frames, cards, icons, or illustrations
- photo crop, border, and placement style
- chapter opener format
- recurring header, footer, and page-number system
- decorative density and whitespace
- transitions between page types

Use the visual DNA as a guide. Do not reproduce copyrighted wording, photos, logos, or a distinctive branded template exactly. See `references/reference-matching-rules.md`.

### 3. Build an exact page manifest

Create a numbered manifest from page 1 through the final requested page. Give every page a purpose and a page type. The manifest must total exactly the user's requested count.

Possible page types include:

- front cover
- title page
- copyright or disclaimer
- dedication
- table of contents
- about the author or brand
- introduction
- chapter opener
- instructional content page
- two-column article page
- list or tips page
- quote or affirmation page
- case study or example
- infographic or process page
- worksheet
- checklist
- tracker
- journal prompt
- recap or key-takeaways page
- resource list
- bibliography or endnotes
- conclusion
- call-to-action page
- back cover

Do not add every page type automatically. Choose only those that support the user's goal. When the user requests a particular page type, include it.

### 4. Plan accurate, useful content

Write the content around a clear reader transformation. Give chapters distinct jobs and avoid repeating the same advice with different headings. Use concrete examples, actionable steps, and relevant exercises where appropriate.

For current, medical, legal, financial, scientific, or other high-stakes claims, research authoritative and current sources before writing. Never invent statistics, direct quotes, laws, medical claims, prices, or citations. Include source notes, references, or disclaimers when the subject requires them. Keep source language paraphrased unless a short quotation is necessary and permitted.

For a commercial or PLR product, create original wording and do not imply that the content has received professional legal, medical, tax, or financial review.

### 5. Lock the design system

Before generating the first interior page, define and maintain one design system:

- exact canvas size and orientation
- safe margins
- palette
- headline, subhead, body, caption, and page-number typography directions
- body-text density target
- grid and column options
- image style
- decorative element rules
- header and footer placement
- page numbering
- chapter divider treatment

The design system may contain several approved page templates, but all templates must visibly belong to the same e-book. Keep spacing, alignment, font feel, footer placement, and page proportions consistent.

### 6. Prepare page-ready copy

Write copy to fit the planned page rather than placing a full manuscript onto a small canvas. Break long material across multiple pages, use short paragraphs, meaningful headings, bullet points when helpful, and clear callouts. Do not shrink text to an unreadable size merely to force excess copy onto one page.

For worksheet or workbook pages, prioritize usable writing space. Reduce decorative elements, oversized headings, and padding before reducing functional space.

### 7. Generate the pages

Generate each page as an individual full-canvas page. Use the exact dimensions requested. Include the page's final copy, final visual hierarchy, page number when applicable, and all required design elements.

Generation rules:

- Use one image-generation request for up to 10 separate pages when supported.
- Maintain the same locked design system across batches.
- Keep a running page ledger so no page is skipped, duplicated, or reordered.
- Name files with zero-padded numbers: `page-001.png`, `page-002.png`, and so on.
- Do not add an exterior desk, device mockup, drop shadow, colored mat, or surrounding background to the actual page files.
- Do not generate a collage as a replacement for separate page images.
- Use diverse but coordinated page layouts so the book is consistent without being monotonous.
- Follow any uploaded reference for structure and atmosphere while keeping content and assets original.

### 8. Quality-control every page

Inspect each page at readable size. Check:

- exact dimensions
- correct page number
- correct page title and chapter
- spelling and grammar
- readable body text
- no warped or garbled letters
- no missing text
- no duplicated paragraphs
- no accidental placeholders
- balanced spacing
- consistent margins
- consistent footer/header placement
- correct image subject and crop
- no accidental logos, watermarks, or unrelated text
- no repeated page designs where variety is expected

Regenerate only defective pages. Keep approved pages unchanged.

### 9. Compile and package

After all pages pass quality control:

1. Put pages in exact numerical order.
2. Compile a high-quality PDF with one image per page and no extra margins or compression artifacts.
3. Confirm the PDF page count matches the manifest.
4. Create an organized ZIP such as:

```text
Ebook_Title_Final/
  01_Individual_Pages/
    page-001.png
    page-002.png
    ...
  02_Complete_Ebook/
    Ebook_Title_Final.pdf
  03_Project_Details/
    page-manifest.txt
    design-spec.txt
    source-notes.txt        # only when applicable
```

Do not include drafts, broken pages, duplicate files, contact sheets, or temporary assets in the final ZIP.

## Reference-style mode

When the user says “make it look like this,” “use this layout,” “match this formatting,” or provides reference pages:

1. Analyze the complete reference set.
2. Summarize its visual DNA internally.
3. Separate reusable design principles from protected content.
4. Apply the design principles to the user's new topic.
5. Maintain the same level of polish across all requested pages.
6. Allow the user to override any part of the reference style.

A useful reference match should feel recognizably inspired by the layout system, not like an unrelated generic template and not like a pixel-for-pixel copy.

## Neutral minimalist editorial preset

The uploaded example that inspired this skill uses a neutral minimalist editorial system. When the user asks for that style, follow the detailed profile in `references/neutral-minimalist-editorial-profile.md`.

Core traits:

- warm ivory or soft cream full-page background
- charcoal or near-black text
- high-contrast editorial serif headings
- clean sans-serif body text
- generous outer margins and controlled whitespace
- thin horizontal rules
- oversized chapter or section headlines
- one- and two-column article layouts
- restrained photography in thin rectangular frames
- discreet footer with title, author/brand, website, and page number
- minimal decoration and no bright gradients, rounded app-style cards, or heavy shadows

## Writing and design boundaries

- Do not promise income, guaranteed outcomes, or professional results.
- Do not use other creators' copyrighted text or photos merely because they appear in a reference.
- Do not fabricate testimonials, credentials, sources, or author biographies.
- Do not use a living artist's exact style when a user asks for direct imitation; instead translate the request into general visual traits.
- Do not create unsafe or deceptive instructions.
- When an e-book includes regulated or high-stakes guidance, frame it as educational information and add appropriate source notes and disclaimers.

## Optional sellable-product extras

Create these only when requested or clearly included in the user's brief:

- matching workbook
- checklists, trackers, templates, forms, or journal prompts
- cover mockup prompts
- product title and subtitle options
- product description
- Etsy, Shopify, Gumroad, Stan Store, or website listing copy
- SEO keywords and tags
- promotional hooks and social captions
- bundle suggestions
- suggested price positioning
- commercial-use or PLR license draft

These extras do not count toward the e-book's requested page total unless the user says they should be inside the e-book.

## Completion response

When the e-book is complete, provide direct links to the final files. State the exact completed page count and list the delivered formats. Keep the completion message focused on the deliverables rather than repeating the entire workflow.
